                A Low-Cost Signal Source
• We want the input signal to be very linear
   – E.g., SFDR > 90dB @ 100 MHz
• How about using a low-cost signal generator?
   – Frequency range limited to 15MHz
   – Large harmonic distortion: -40dBc for fin > 1MHz
   – Far away from what we need!

                                                       10
                        Filter Distortion
• Filters themselves generates distortions!
   – Many filters are designed to operate with a small signal swing
        • In ADC testing, the input swing is usually large ~ 2V
   – Low-cost filters may not satisfy the linearity requirement
        • The self-generated distortion may be even larger
• Filter distortion is usually not specified
   – Need to call manufacturer
         • High-end filters usually have HD<-85dBc, but don't trust your
           filters blindly
   – Use a spectrum analyzer to test the filter distortion before using it
         • The spectrum analyzer itself generates distortion!
              – We can place attenuators in front of the spectrum
                 analyzer

                                                                        11
                       Clock Generator

• The clock source needs to have a high quality
   – We do not care about distortion
   – We care about phase noise or jitter
• High frequency clocks are always sine wave like
   – We need a clock receiver to turn it into a square wave
   – Be careful about the phase noise of the clock interface circuits
        • Ideally, the jitter should be limited by the clock source




                                                                        12
                   Phase Noise and Jitter
• For a clock generator, its phase is not fixed, but follows a random
  walk


                           n2 = 2 Dt
• Where D is the phase diffusion constant
• Low-end signal generator:
   – Large D, cycle-to-cycle jitter  100ps rms
• High-end signal generator:
   – Small D, cycle-to-cycle jitter  0.1ps rms




                                                                        13
                 Jitter from Other Circuits
• Other clock interface circuits also contribute jitter.
• Clock jitter from other circuits can be minimized by:
   – Separate supplies
   – Separate analog and digital clocks
   – Short inverter chains between the clock source and the
      destination
• Jitter induced noise has the following unique properties
    – RMS noise proportional to input frequency
    – RMS noise proportional to input amplitude
• Thus, it is easy to identify when ADC noise is jitter limited

                ADC Digital Output Signaling

• CMOS signaling works well for low fCLK<100MHz
• For high frequencies signaling, we prefer LVDS
   – Low voltage differential signaling
• LVDS vs. CMOS:
   – Higher speed ☺
   – More power efficient ☺
   – Less noise ☺
   – Lower swing 
   – Two pins/bit 




    Analog Devices application note 586: "LVDS data outputs for high speed ADCs"

                                                                                   22
              How to Acquire ADC Output
• Several options:
   – Logic analyzer with PC interface
   – FIFO board, interface to PC DAQ card
   – Oscilloscope
• We can build on-chip DACs and send multiple bits through one pin
   – It reduces the pin count ☺
   – It lowers the power ☺
• We can use an oscilloscope to capture the DAC outputs and re-
  quantize it to obtain the ADC digital output
   – This works especially well for ultra-high-speed ADCs
       • Logic analyzers usually cannot work beyond 2GS/s
       • High-speed (e.g., 50GS/s) oscilloscopes are easy to find

                    Spectral and DNL/INL
• We can perform FFT in Matlab to measure spectral metrics
• How about DNL/INL for a DAC?
   – "Trivial", apply codes and use "a good voltmeter" to measure
     outputs
• How about DNL/INL for an ADC?
   – Need to find "decision levels", i.e. input voltages at all code
     boundaries
   – We can measure code widths through histogram testing

                         Histogram Test




• Code width is proportional to the number of code occurrences
• Ramp needs to be sufficiently slow to provide enough code occurrence
   – For a 16-bit 100 kS/s ADC, to provide on average 100 occurrence per
     code, we need the ramp period to be 216100/100k  64 seconds

% sinusoid

                                       % truncate at least first and last

                                       lsb= sum(hlin_trunc) / (length(hlin_trunc));

          Limitations of Histogram Testing
• Histogram testing assumes monotonicity
   – E.g. “code flips” will not be detected
• Dynamic sparkle codes produce only minor DNL/INL errors
   – E.g. 123, 123, …, 123, 0, 124, 124, …
   – Must look directly at ADC output to detect
• Noise can smear DNL
   – E.g. 9, 9, 9, 10, 9, 9, 9, 10, 9, 10, 10, 10, …
   – INL is more robust against noise, need to look at both INL and DNL
• Reference
   – B. Ginetti and P. Jespers, “Reliability of Code Density Test for High
     Resolution ADCs,” Electron. Letters, pp. 2231-2233, Nov. 1991.
